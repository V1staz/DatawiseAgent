\begin{frame}{复现以后，我们真正关心的问题}
\begin{columns}[T]
\begin{column}{0.49\textwidth}
\begin{block}{原文里有用的现象}
弱模型可以靠 notebook-style 的长交互补一部分能力：
\begin{itemize}
  \item 先 planning；
  \item 写 code 并 execution；
  \item 根据报错 debugging；
  \item repair 后继续推进。
\end{itemize}
\end{block}
\end{column}
\begin{column}{0.49\textwidth}
\begin{alertblock}{但复现后看到的问题}
多跑几轮不一定更好：
\begin{itemize}
  \item 有些题只是答案格式错；
  \item 有些题是统计口径错；
  \item hard 题多分支搜索可能选错；
  \item DataModeling 常常卡在协议和评估格式。
\end{itemize}
\end{alertblock}
\end{column}
\end{columns}
\takeaway{“时间换性能”只是我们的概括说法；更准确地说，是弱模型通过更多 planning / execution / debugging / repair 得到更稳的结果。}
\end{frame}

\begin{columns}[T]
\begin{column}{0.48\textwidth}
\textbf{主线：让时间更有效}
\begin{itemize}
  \item 先固定题目约束和数据结构；
  \item 执行后检查关键统计语义；
  \item 最终答案不再从长日志里乱抽。
\end{itemize}
\end{column}
\begin{column}{0.48\textwidth}
\textbf{延伸：再控制资源}
\begin{itemize}
  \item 简单阶段规则化；
  \item 中等任务用弱模型 + light harness；
  \item hard 或 verifier fail 再上强模型。
\end{itemize}
\end{column}
\end{columns}
\takeaway{成本控制不是主线本身，而是知道“时间该花在哪里”之后的自然延伸。}
\end{frame}

\begin{frame}{两个 benchmark 的错法不一样}
\footnotesize
\begin{tabularx}{\textwidth}{p{0.18\textwidth} X X}
\toprule
Benchmark & 复现后看到的常见错法 & 更合适的 harness \\
\midrule
InfiAgentBench &
答案格式、小数位、引号；统计口径；预处理顺序；相关性/显著性判断；特征工程公式；最终答案抽取漏掉或抽错 &
\textbf{answer-aware}: DataCard, Contract, Skill checklist, Verifier, Final Block \\
\midrule
DataModeling &
submission / performance 文件没生成；评估格式不匹配；metric 类型错配；jaccard 文本指标收到数值列 &
\textbf{protocol-aware}: submission checker, metric checker, performance parser, evaluation adapter \\
\bottomrule
\end{tabularx}
\takeaway{我们不是统一加长 prompt，而是把额外时间放到每类任务最容易翻车的地方。}
\end{frame}

\begin{frame}{InfiAgentBench：answer-aware harness 做了什么}
\begin{columns}[T]
\begin{column}{0.54\textwidth}
\footnotesize
\begin{tabularx}{\textwidth}{p{0.28\textwidth} X}
\toprule
模块 & 解决的问题 \\
\midrule
DataCard & 不让模型每题重新摸索列名、dtype、缺失值、范围。 \\
Contract & 把 answer name、rounding、列、过滤条件、方法写清楚。 \\
Skills & 对 correlation、outlier、ML、format 等题型给检查清单。 \\
Verifier & 检查列是否存在、样本是否为 0、p-value / abs(r) / final format 等。 \\
Final Block & 主 agent 先给机器可读答案块，再确定性转 \code{@answer[value]}。 \\
\bottomrule
\end{tabularx}
\end{column}
\begin{column}{0.43\textwidth}
\begin{block}{这不是“多写提示词”}
它把原本散在长日志里的东西拆出来：
\begin{itemize}
  \item 题目约束提前固定；
  \item 过程检查独立执行；
  \item 答案抽取变成确定性步骤。
\end{itemize}
\end{block}
\end{column}
\end{columns}
\takeaway{InfiAgentBench 的瓶颈很多时候不是不会写代码，而是口径和最终答案不稳。}
\end{frame}

\begin{frame}{light vs full：为什么现在更偏向 light-first}
\begin{columns}[T]
\begin{column}{0.48\textwidth}
\begin{block}{light 做了什么}
\begin{itemize}
  \item DataCard
  \item Contract
  \item basic skills
  \item Finalizer
\end{itemize}
\end{block}
\begin{beamercolorbox}[wd=\textwidth,sep=0.8ex,rounded=true]{chip}
\textbf{结果：}ABQ +10.63，runtime +16.79s
\end{beamercolorbox}
\end{column}
\begin{column}{0.48\textwidth}
\begin{alertblock}{full 额外做什么}
\begin{itemize}
  \item search / memory
  \item heavier oracle
  \item heavier verifier
  \item 更多候选和修复轮次
\end{itemize}
\end{alertblock}
\begin{beamercolorbox}[wd=\textwidth,sep=0.8ex,rounded=true]{chip}
\textbf{结果：}比 light 再 +4.26 ABQ，但 +45.76s
\end{beamercolorbox}
\end{column}
\end{columns}
\takeaway{默认 full-everywhere 不划算；更合理的是 light-first，失败或 hard 题再升级。}
\end{frame}

\begin{frame}{一个具体坑：task 733 卡死在哪里}
\begin{columns}[T]
\begin{column}{0.47\textwidth}
\begin{alertblock}{原问题}
FinalAnswerBlock 的 JSON 被写进 Python code cell。
\begin{itemize}
  \item JSON 里的 \code{false/null} 进入 Python；
  \item 触发 \code{NameError}；
  \item debug loop 反复修，整题卡住。
\end{itemize}
\end{alertblock}
\end{column}
\begin{column}{0.50\textwidth}
\begin{block}{修复后}
\begin{itemize}
  \item final block 只进 markdown / metadata / reformat 输入；
  \item code-cell guard 检查 \code{true/false/null}；
  \item 加 request timeout 和 continue-on-error。
\end{itemize}
\vspace{0.3em}
\smallnote{复跑：harness\_light success，harness\_full success。}
\end{block}
\end{column}
\end{columns}
\takeaway{这类问题不是模型能力问题，是“答案通道”和“执行通道”混了。}
\end{frame}

\begin{frame}{合理预期：只作为后续实验目标}
\footnotesize
\begin{tabularx}{\textwidth}{p{0.16\textwidth} X X}
\toprule
档位 & InfiAgentBench full 257 \hypothesis{} & DataModeling \hypothesis{} \\
\midrule
Conservative & weak + light 优于 weak baseline，ABQ 约 +2--4pt & 减少无效 submission / performance 缺失 \\
Target & weak + light 约 +5--8pt，hard 题可能更明显 & complete rate 预期改善，performance 可能小幅上升 \\
Optimistic & weak + full 或 gated harness 约 +8--12pt，缩小 weak-to-strong gap & silent failure 转成可恢复失败 \\

\end{alertblock}
\takeaway{PPT 里可以给目标，但要把目标和真实结果分开。}
\end{frame}

\begin{frame}{Resource-aware routing：谁来花时间}
\footnotesize
\begin{tabularx}{\textwidth}{p{0.14\textwidth} p{0.24\textwidth} X}
\toprule
层级 & 默认资源 & 怎么跑 \\
\midrule
easy & 规则 / 小 instruct / finalizer & schema、列名、格式、final block 尽量确定性；低风险题 one-shot 或 0 次 LLM。 \\
medium & 14B 或弱模型 + contract + verifier & 用契约固定口径；verifier fail 后只修失败点。 \\
hard & 32B / thinking + search + fallback & 复杂推理和多候选选择交给强模型，但只在高风险或校验失败时启用。 \\
finalization & deterministic & Final Block 到 \code{@answer[value]} 程序渲染，去掉 reformat 对话。 \\
\bottomrule
\end{tabularx}
\takeaway{模型路由不是为了“全程用小模型”，而是把强模型留给真的需要它的阶段。}
\end{frame}

\begin{frame}{当前状态 vs 目标差距}
\footnotesize
\begin{tabularx}{\textwidth}{p{0.24\textwidth} p{0.18\textwidth} X p{0.22\textwidth}}
\toprule

\midrule
